# PRE_TOURNAMENT_ACCEPTANCE.md

## Предтурнирная приёмка MVP

Цель: за 20–30 минут подтвердить, что приложение готово к реальному миникапу:

**10 игроков → 5 игр → итоговый рейтинг → Excel**

Проверку выполнять на том же сервере, телефоне и браузере, которые будут использоваться на турнире.

---

## 1. Старт системы

- [ ] Production-сборка запускается без ошибок.
- [ ] PostgreSQL доступен.
- [ ] Все Prisma migrations применены.
- [ ] Главная страница открывается с телефона.
- [ ] После обновления страницы приложение продолжает работать.
- [ ] Интерфейс нормально отображается примерно на `390×844`.

**NO-GO:** приложение не открывается, БД недоступна, миграции не применяются или есть критические ошибки загрузки.

---

## 2. Создание тестового миникапа

Создать временный турнир `PRE-TOURNAMENT TEST`.

- [ ] Введены ровно 10 уникальных ников.
- [ ] Турнир успешно создаётся.
- [ ] Создаются ровно 5 туров.
- [ ] Тур 1 доступен для начала.

---

## 3. Рассадка

- [ ] Рассадка содержит места `1–10`.
- [ ] Каждый из 10 игроков присутствует ровно один раз.
- [ ] `Перерандомить` работает до подтверждения.
- [ ] После подтверждения рассадку нельзя изменить обычным действием.
- [ ] После reload подтверждённая рассадка сохраняется.

**NO-GO:** пропадает/дублируется игрок, меняется подтверждённая рассадка или данные теряются после reload.

---

## 4. Проверка игровой партии

Не требуется проводить полноценную длинную игру. Пройти ускоренный сценарий.

### Роли

- [ ] Можно назначить `1 DON + 2 MAFIA + 1 SHERIFF`.
- [ ] Остальные 6 игроков становятся `CIVILIAN`.
- [ ] Невалидный состав ролей не позволяет начать игру.
- [ ] После старта роли скрыты privacy-safe способом.

### День

- [ ] Первая речь начинается с №1.
- [ ] Таймер запускается и завершается корректно.
- [ ] Фол ставится одним быстрым действием.
- [ ] Undo фола работает.
- [ ] Выставление игрока сохраняется.
- [ ] После reload текущая игра продолжается с сохранённого состояния.

### Голосование

- [ ] Кандидаты идут в порядке выставления.
- [ ] Простое голосование выводит нужного игрока.
- [ ] При равенстве открывается автокатастрофа.
- [ ] После повторного голосования flow продолжается корректно.

### Ночь

- [ ] Можно записать `Промах` или `Отстрел`.
- [ ] Проверка Дона выдаёт правильный результат.
- [ ] Проверка Шерифа выдаёт правильный цвет.
- [ ] ТЧ сохраняется и рассчитывается из фактических ролей.

### Завершение

- [ ] Система предлагает победителя при выполнении условия победы.
- [ ] Игра не закрывается без подтверждения судьи.
- [ ] После подтверждения игра переходит в `SCORING`.

**NO-GO:** невозможно продолжить штатный flow, неверно определяется победитель, пропадает состояние игры или возникает блокирующая ошибка.

---

## 5. Scoring

На тестовой игре проверить минимум один ДБ, одну ТЧ и один штраф.

- [ ] Base определяется автоматически по победившей команде.
- [ ] ДБ выбирается только из допустимых значений.
- [ ] Невалидный ДБ отклоняется.
- [ ] ТЧ подставляется автоматически.
- [ ] Штрафы суммируются.
- [ ] Итог игры считается автоматически.
- [ ] Draft scoring сохраняется после reload.
- [ ] После `Закрыть игру` обычное редактирование блокируется.

---

## 6. Переход между турами

- [ ] После закрытия игры 1 доступен тур 2.
- [ ] Новый тур использует тот же состав из 10 игроков.
- [ ] Для нового тура можно сгенерировать новую случайную рассадку.

Для предтурнирной проверки необязательно вручную проводить все пять полных игр, если automated/integration tests уже зелёные.

---

## 7. Итог миникапа

Использовать тестовые/ускоренные данные, чтобы получить 5 закрытых игр.

- [ ] После 5-й игры доступна финализация.
- [ ] Рассчитываются компенсационные баллы.
- [ ] КБ отображаются отдельной колонкой.
- [ ] Финальная таблица содержит 10 игроков.
- [ ] Места отсортированы по ranking engine.
- [ ] При полном равенстве система требует ручной жребий, а не выбирает случайно.
- [ ] После жребия финализация завершается.

Если возникает DRAW с неопределённым КБ:

- [ ] система блокирует финализацию;
- [ ] показывает конкретного игрока/тур;
- [ ] позволяет внести решение Главного судьи с причиной.

---

## 8. Excel

- [ ] Кнопка `Экспорт Excel` доступна после финализации.
- [ ] Файл `.xlsx` скачивается и открывается.
- [ ] Есть лист `Итоги`.
- [ ] Есть лист `Игры`.
- [ ] В `Итоги` — 10 игроков + строка заголовков.
- [ ] В `Игры` — данные пяти игр.
- [ ] Значения итогов совпадают с экраном приложения.

**NO-GO:** Excel не скачивается/не открывается либо итоговые значения отличаются от интерфейса.

---

## 9. Телефон и сеть

На реальном судейском телефоне:

- [ ] основные кнопки удобно нажимаются одной рукой;
- [ ] нет перекрывающихся элементов;
- [ ] таймер полностью виден;
- [ ] карточки игроков читаются;
- [ ] роли невозможно случайно показать игрокам;
- [ ] online/offline indicator работает;
- [ ] после краткого отключения сети приложение не теряет уже подтверждённые данные;
- [ ] PWA устанавливается/открывается в предполагаемом режиме использования либо браузерный запуск полностью устраивает.

---

## 10. Перед самым турниром

- [ ] Создана резервная копия PostgreSQL либо проверен рабочий способ её сделать.
- [ ] Из БД удалён `PRE-TOURNAMENT TEST`.
- [ ] Создан чистый реальный миникап.
- [ ] Проверены все 10 ников.
- [ ] Телефон заряжен.
- [ ] Есть зарядка / power bank.
- [ ] Есть стабильный доступ к адресу приложения.
- [ ] Excel export проверен хотя бы один раз на текущем production build.
- [ ] Не выполняются миграции, обновления зависимостей или рефакторинг непосредственно перед стартом.

---

# GO / NO-GO

## МОЖНО ПРОВОДИТЬ — GO

Турнир можно проводить, если одновременно выполнено:

- [ ] нет ни одного `NO-GO` дефекта;
- [ ] создание турнира и рассадка работают;
- [ ] тестовая игра доходит до `SCORING`;
- [ ] данные переживают reload;
- [ ] scoring корректно закрывает игру;
- [ ] после 5 игр работает финализация;
- [ ] итоговая таблица строится;
- [ ] Excel экспортируется;
- [ ] приложение удобно работает на реальном телефоне;
- [ ] база данных доступна и есть план резервного копирования.

## НЕЛЬЗЯ ПРОВОДИТЬ — NO-GO

Не начинать реальный миникап, если есть хотя бы один из дефектов:

- потеря игровых данных;
- невозможность продолжить игру после reload;
- неверное определение победителя;
- неверный scoring / КБ / ranking;
- подтверждённая рассадка может самопроизвольно измениться;
- невозможно закрыть игру или перейти к следующему туру;
- финализация не работает;
- Excel содержит отличающиеся от приложения результаты;
- production-БД нестабильна или недоступна;
- на телефоне невозможно надёжно выполнить основные судейские действия.
