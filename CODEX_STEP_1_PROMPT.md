# CODEX_STEP_1_PROMPT.md

Прочитай `AGENTS.md` и `PROJECT_SPEC.md` полностью. Затем реализуй только **Step 1 — Foundation + Tournament**.

Цель этой итерации: после запуска приложения я должен создать миникап с названием и ровно 10 никами, получить 5 туров, сгенерировать случайную рассадку первого тура по местам 1–10, при необходимости перерандомить её до подтверждения, подтвердить и после reload увидеть те же сохранённые данные.

## Сделай

1. Инициализируй/приведи проект к baseline из `PROJECT_SPEC.md`:
   - Next.js App Router;
   - TypeScript strict;
   - Tailwind;
   - PostgreSQL;
   - Prisma.

2. Создай минимальную schema для Step 1:
   - `Organization`
   - `Tournament`
   - `Player`
   - `TournamentPlayer`
   - `Round`
   - `Game`
   - `GameSeat`

   Не добавляй сейчас Nomination/Vote/NightAction/Scoring tables — они появятся в следующих шагах.

3. Создай одну default Organization без UI управления ею.

4. Реализуй создание миникапа:
   - название обязательно;
   - ровно 10 непустых ников;
   - ники должны быть уникальны внутри турнира после trim/case-normalization;
   - создать 5 rounds;
   - не делать auth.

5. Реализуй экран турнира:
   - название;
   - 10 игроков;
   - 5 туров;
   - статусы;
   - понятное следующее действие.

6. Реализуй рассадку первого/следующего доступного тура:
   - серверный Fisher–Yates;
   - cryptographic randomness;
   - 10 уникальных игроков -> места 1..10;
   - `Перерандомить` разрешено до confirmation;
   - `Подтвердить рассадку`;
   - после confirmation обычное изменение запрещено;
   - данные persisted.

7. Сделай mobile-first UI без декоративного overengineering.

8. Добавь high-value tests:
   - нельзя создать турнир не с 10 игроками;
   - duplicate nicknames внутри турнира отклоняются;
   - создаётся ровно 5 rounds;
   - seating всегда содержит все 10 игроков ровно один раз и места 1..10;
   - confirmed seating сохраняется и не меняется обычным regenerate action.

9. Добавь короткий README-раздел с локальным запуском и env variables, если его ещё нет.

## Не делай в этой итерации

Не реализовывай:

- авторизацию;
- экран ролей;
- игровую state machine;
- таймер;
- фолы;
- nominations;
- голосование;
- ночь;
- scoring;
- КБ;
- ranking;
- Excel;
- PWA;
- дополнительные форматы турниров.

Не создавай «заглушечные красивые экраны» для следующих шагов.

## Definition of Done

Итерация завершена только если:

- приложение запускается локально;
- миграция Prisma применяется;
- можно создать один миникап с 10 игроками;
- видно ровно 5 туров;
- можно сгенерировать/перегенерировать рассадку доступного тура;
- можно подтвердить рассадку;
- reload не теряет данные;
- typecheck/lint/tests проходят.

После реализации остановись. Не переходи к Step 2.

В финальном отчёте перечисли:
- ключевые файлы;
- schema/migration;
- команды запуска;
- команды проверок;
- результаты tests/typecheck/lint;
- любые реальные блокеры или assumptions.
